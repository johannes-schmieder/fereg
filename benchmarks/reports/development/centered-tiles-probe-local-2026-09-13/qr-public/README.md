# Centered one-FE tiles: reject native adoption after QR cost review

The scoped centered implementation is **rejected for adoption in its tested
form**. Stable means and streamed moments/scores reduce native memory, but all
five prescribed QR controls violate the protected complete-command envelope.
The earlier full-rank IID screen also missed its memory/time condition. Preserve
the accepted matrix route; do not obtain a passing result by excluding deficient
models, relaxing rank policy, or pooling additional favorable seeds.

This concludes the bounded P5 implementation/evaluation. Its first four work
items were implemented in an isolated prototype and tested, not adopted. The
conditional PPML extension is declined because there is no acceptable OLS winner.
This does not prove that all centered algorithms are unprofitable. R3's later
coefficient-space investigation may revisit a materially different mechanism;
merely repeating this layout or its QR storage choice is not a new hypothesis.

## Source, public failure and repair

Accepted numerical baseline is `257f4ce`, with evidence HEAD `436fe2a` and
baseline plugin `c64ead07`. The preceding QR-capacity source was built separately
as plugin `c8817a0b`; both architectures recompiled the core and plugin and the
actual arm64 ABI check passed. Its first public near-capacity pair passed on the
baseline but returned r(498) on the candidate. A separate noisy invocation
identified the precommit requirement that fast mode report zero scratch bytes;
previous e(b) remained intact. The other four pairs did not run on that artifact.
The failure is not a successful numerical or performance comparison.

A subsequent experimental report flag identifies centered QR storage explicitly.
Publication checks its exact `8*N*K` file bound and final axes/eligibility, while
ordinary fast and low-mode checks remain. The core already checked the file and
resident staging capacities before creation. This reporting extension is not a
proof of full estimator admission and is withdrawn with the rejected route.

The [182-input identities](build-identities-v6.json), [complete patch](prototype.patch)
and isolated plugin `840092dd` bind the final experiment. Both architecture
builds and actual arm64 ABI pass. The installed plugin is unchanged and was not
used as the baseline. [Inputs](input-recipes.json) preserve original generators,
column hashes and frozen data recipes. Near-capacity seed labels do not vary the
deterministic data and are not independent repetitions.

## Prospective command and memory results

All five original public cases were rerun under new run names after the repair,
with rotated order, fresh processes, a small warm-up and no concurrent builds or
tests. Each is a single prospective control pair. There was no seed search or
broader primary/protected campaign after the failures. Seconds below include
estimation, inference and publication.

| QR control | Command seconds, baseline → candidate | Change | Native peak MB, baseline → candidate |
|---|---:|---:|---:|
| Near-capacity unit IID | 0.034 → 0.051 | +50.0% | 6.38 → 4.49 |
| Near-capacity AW robust | 0.047 → 0.063 | +34.0% | 7.68 → 4.62 |
| Near-capacity FW clustered | 0.046 → 0.062 | +34.8% | 7.88 → 4.82 |
| Near-capacity PW two-way cluster | 0.046 → 0.065 | +41.3% | 8.08 → 5.02 |
| Wide deficient AW robust | 1.366 → 1.898 | +38.9% | 93.40 → 55.53 |

The four near-capacity cases have N=16,384, 16 finite controls, 7,736 groups and
rank 15; the wide case has N=98,304, 50 controls and rank 49. All request four
native workers. All candidate peaks fit unchanged public models in these pairs.
Sampled process RSS rises for AW robust and the wide case; native allocation
savings are not universal RSS savings.

Candidate scratch-file capacities are 2,228,224 and 40,108,032 bytes respectively,
versus zero on baseline. These are **file sizes, not bytes transferred**. Actual
read/write traffic and isolated I/O wait are unmeasured. The complete fallback
cost is included in command time. All first-screen losses exceed the prospective
max(10 ms, 5%) review envelope. The wider +532 ms loss rules out this implementation
under the preserved protected-control criterion despite 40.5% native-peak savings.

Two separate profiles confirm the fitting regression without being pooled with
the screens. Near IID is 0.033→0.052 seconds, with fit scope 0.02186→0.03972.
Wide AW is 1.446→1.868, with fit 1.18028→1.70839. Wide score construction and
certification improve 0.15605→0.04757, but this does not offset the fit cost.
The candidate fit scope does not isolate QR arithmetic from I/O; no precise
hardware-traffic attribution is claimed. [Phase profiles](phase-profiles.json)
retain warm-up records separately in each ordered trace; the last record is the
measured target.

## Science, validation and limits

All seven successful pairs preserve exact samples, rank/status, DoF, FE and
cluster/subset structure. Full b/V comparisons pass unchanged registered
tolerances and native certificates; maximum full b/V differences are about
7.3e-16/3.5e-12 over the screens. Rank is 15/49 as prescribed. Solver diagnostics
and scratch differences are retained in the numeric archive rather than asserted
identical across numerical routes. No finite-rank or covariance policy changed.

Thirty-five centered core tests and 46 plugin tests pass on the final source,
including twelve near-capacity weight/cache fits, forged scratch reports,
ordinary low/fast behavior and transactional checks. The plugin substring filter
also selected PPML tests; all are counted in the 46, not described as additional
independent tests. Parent output interleaving is handled by enumerated names plus
the terminal 46-pass result. There are **81 distinct final passing tests**.
The prior scratch/robust/clustered suites remain separate source-bound evidence.

The first test command used an unavailable Cargo launcher. The first core run
then had two report-equality failures because the fixture normalized scratch size
but not the new origin flag. The corrected fixture checks flag/size consistency
before comparing the other execution fields; scientific assertions and production
arithmetic were unchanged. All failed attempts remain in this archive.

Full overlapping estimator memory proof remains incomplete. The component cap,
near-limit tests and admitted measured peaks do not establish universal bounds.
Cost rejection stops adoption before that proof or a PPML extension. There is
no new automatic route, installed binary, SCC job, qualification, external
comparison or push from this experiment. The separate selected saved-output
candidate is preserved for an independent P6 evaluation.
