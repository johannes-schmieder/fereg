# P6 selected-output mask: reject the standalone optimization

Reject the three-file change that forwards an unrequested combined-output mask
to the existing direct/SD/remainder-LSMR recovery finisher. It avoids one possible
N-double output allocation without changing requested channels, certificates or
recovery arithmetic, but none of the three prospective targets meets the fixed
complete-command/native-memory adoption threshold. Accepted source is restored.
This is not completion of P6's broader saved-effect retention/recovery evaluation.

## Source and validation

The numerical baseline is `257f4ce`, evidence HEAD `25b1bb3`. [Identities](identities.json)
bind all 176 inputs, the [three-file patch](implementation.patch), accepted plugin
`c64ead07` and isolated candidate `79ff38b2`. Both architecture builds recompiled
the core/plugin and the actual arm64 ABI check passed. Installed dist is unchanged.
This candidate contains no centered-tile code or experimental scratch-report policy.

Seventeen focused topology/recovery tests pass. The independent [oracle](oracle.do)
uses Stata explicit-dummy regressions on 3,072 observations and passes 48 fits per
artifact: unit/AW/FW/PW, one/two FE, fast/low, all/partial saved channels, residuals,
weighted normalization and combined-output reconstruction. Previous results and
absence of new output variables are checked after an injected precommit failure.
Combined outputs use the existing internal transaction interface; no new public
Stata syntax is introduced. [Validation](validation.json) records both terminal
sentinels. No oracle or fit failed in this isolated experiment.

## Prospective screen

The [protocol](protocol.md) precedes timing. Three single-seed pairs rotate arm
order in fresh Stata processes after a small warm-up; complete estimation,
inference and output publication are inside the timer. No tests/builds overlap.
The threshold was >=5% and >=10 ms command savings, or >=5% and >=2 MiB native
peak savings with <=5% command slowdown.

| Case | N / K / workers | Command seconds | Native peak MB | Decision |
|---|---|---:|---:|---|
| Unit one-FE saved | 983040 / 1 / 4 | 0.207 → 0.207 | 96.95 → 96.95 | No gain |
| AW low one-FE saved, missing | 983040 / 1 / 4 | 0.329 → 0.315 | 99.99 → 99.99 | 4.3% command gain misses threshold |
| PW clustered two-FE partial saved, missing | 245760 / 10 / 16 | 0.409 → 0.412 | 398.11 → 394.59 | 0.9% peak reduction misses threshold |

All b/V, samples, statuses, DoF, FE/cluster/subset structure and requested saved
values are exact; the required independent native certificates pass. Complete
solver/runtime numeric tables, scratch fields and retry diagnostics are retained
in the archive. The native decrease on the two-FE case was not traced and is
larger than one skipped vector; it is not assigned causally to this change.

Unit/AW modeled peaks are 121.90/115.08 MB and both artifacts fit them. The PW
case reports only 107.15 MB modeled against 398.11/394.59 MB observed. Both arms
therefore expose a **pre-existing P0 accounting gap**, not successful memory
admission evidence. PW sampled RSS rises 0.608→0.624 GiB. Other sampled RSS
movements are not treated as reliable native allocation changes.

The prescribed separate AW low profile is 0.310→0.313 seconds, with identical
native peak. Its available trace has nearly unchanged preparation/statistics
and does not isolate the skipped recovery vector. No output-phase or hardware
traffic gain is inferred from that trace. Profiles are not pooled with the
screen, and there were no additional primary seeds or protected performance
campaign after rejection. A skipped N-double payload remains a source-derived
mechanism observation, not an accepted whole-command optimization.

## Remaining saved-output work

Existing one-FE Auto already returns no retained FE coefficient batch in the
inspected saved-output route. Public fast OLS more generally still requests
coefficient retention when any saved channel is named, while final publication
already constructs `y - xb - residual` and can recover from that accepted target.
The next substantive P6 comparison is whether eligible two-FE fits can omit that
retention and use the existing final-state recovery, including all recovery,
fallback and memory costs. The two-FE accounting gap makes that lifetime audit
necessary; this small mask experiment does not establish its safety or value.

[Comparisons](comparisons.json), [phase traces](phase-profiles.json),
[numeric archive](numeric-evidence.zip), [receipt](receipt.json) and
[restoration proof](restoration.json) preserve the evidence. No dependency,
scientific policy, installed artifact, cluster job, agent, qualification or push
changed. P6 saved outputs remains open.
