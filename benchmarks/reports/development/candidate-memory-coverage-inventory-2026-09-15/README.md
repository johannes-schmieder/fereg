# Memory construction coverage and reviewed allocation inventories

Development evidence only; no production candidate, platform qualification,
complete-action memory certificate or performance gain is claimed.

## Implemented

PPML's base preflight now covers construction of the owned FE design for all
routes, including MAP and exploratory Mu, which bypass specialized LSMR/CMG
admission. The checked summary charges all retained effect descriptors, codes,
memberships, level offsets/sentinels and slope payloads plus the largest single
effect's simultaneously live count/cursor workspace. It preserves the previous
envelope wherever that was larger. Planning uses scalar arithmetic and creates
no observation-sized reporting allocation. Numerical kernels, samples, weights,
rank/status, tolerances and publication behavior are unchanged.

The singleton-rich one-FE test demonstrates that the previous topology component
can be smaller than construction storage. This identifies a component omission;
it does not establish an observed whole-action cap breach. Sequential effects,
slope descriptors, overflow and exact/one-byte-short fast/low budgets are tested.

The reviewed v18 OLS allocation guard covers the new `memory/` helper directory
and pins four exact replacement boundaries from `a765c33`. Original F0 pins,
literal/dispatch bindings and forbidden OLS-to-PPML/session routes remain
protected; v17 and its failed receipts are unchanged. The
[review](../../../../docs/allocation_inventory.md) maps changes to accepted
ADRs and receipts. `inventory-delta.json` retains the 41 changed source records;
`boundary-review.json` retains before/after canonical bodies. A regenerated
manifest cannot approve a changed boundary body.

A separate v1 action inventory covers all 121 Rust source files under the core
and plugin, including PPML, separation and session bodies excluded by the
OLS-only guard. It inventories 2,505 allocation-syntax sites and production
structure/literals, including conservative out-of-line test-module counts.
These are syntax counts, never a byte or production reachability estimate.
Both inventories run through the repository checker and Python tests.

## Limits and preserved failures

The first Python run encountered stale mutation anchors, a pre-format inventory
and a manifest refresh while tests were reading it. That failed log is retained;
the final run uses fixed inputs and is recorded in `validation.json`.
The first repository-check launch used Apple's license-blocked Git; the later
launch explicitly uses the available Homebrew Git. Its broader failure remains:
pre-existing STATUS heading checks, nested historical STATUS files, and the
stale exact public `feppml.ado` wrapper check. Both new allocation audits pass;
this report does not label the complete repository check green.

Whole-action parent/frame overlap, nested metadata, opaque dependency capacities
and saved/publication storage still need complete coverage. The public base
fields and wires are unchanged, and no complete-action peak or ratio is emitted.
The existing German and three-FE reproductions remain historical evidence for
their own artifacts. Xcode acceptance, exact candidate freeze, platform/install
checks, deterministic archives, Windows and formal release remain separate gates.
