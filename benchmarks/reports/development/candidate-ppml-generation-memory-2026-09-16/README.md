# PPML input, prepared-generation and strict-checkpoint memory

This development checkpoint closes named owner/admission omissions. It does
**not** establish complete whole-action memory coverage or qualify a release.
The source is isolated snapshot `5240e58-generation-capacity4`, based on main
`5240e589400c888690666265263ad96f9b694aa6`. The incremental baseline is the
unpublished `5240e58-worker-retirement1`, not committed main. The tested source,
artifacts, fixed inputs and reference lock are bound in the receipts below.

## Changes

- Charge transferred request and raw-input capacities for core callers. Only
  the excess over an embedding's observed resident parent is added, avoiding a
  duplicate plugin charge. Classification still precedes materialization.
- Bound retained prepared generations, including factor-only/cluster-only
  sources, level tables, recipes, topology descriptors and the original
  reported coefficient axis. Preserve prior larger allowances. Add the
  supplement to both old and replacement generations when they coexist.
- Validate actual retained capacities before accepting each generation.
  Rejection restores temporary candidate masks and probability weights;
  generation publication remains transactional.
- Include initial generation construction in the preparation timer/allocation
  window. Later rebuilds remain inside their requesting separation method.
- Charge the specialized strict-checkpoint caller's copied active-column
  identities. This fifth K-sized index bank lives beside the installed candidate
  and rollback until engine refresh. Slot-heavy models can make this installed
  boundary dominate the earlier assembly boundary.

The numerical kernels, rank policy, tolerances, row classifier, weight semantics
and public memory field definitions/wire are unchanged. The preparation phase
now measures work that previously occurred outside its window.
