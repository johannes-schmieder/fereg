# PPML metadata, session parents and repository guard repair

Development component validation; no complete-action memory certificate,
performance improvement or production candidate is claimed.

## Implemented changes

PPML admission now includes three scalar metadata charges: retained nested
recipes/effect/cluster metadata, preparation construction metadata, and result
metadata. The preparation bound includes the source-availability model copy,
component/operator strings, synthetic terms, bindings and bound effect identities.
It is calculated without observation-sized reporting allocations. Compact model
construction and an atomic replacement generation include their own metadata
beside the still-live parent. Final generation rebasing preserves the initial
metadata reservation and checks actual prepared nested capacities against it.

The fitted-parent sums include the boxed IRLS owner and the copied coefficient,
FE and cluster publication metadata. Partial FE saves reserve every declared
channel's metadata. The reusable shared session's separate row workspace adds
K doubles to its vector bank. Publication validation uses optional-cell
predicates instead of three allocated index inventories, preserving the exact
allowed Stata-missing positions and scientific/structural error classes.

Session capacity observation now includes the accepted fit, retained within
metadata and frozen basis. It sums workspace and current-step capacities where
both exist. Tests distinguish the frozen step, strict candidate plus rollback,
and post-commit canonical fit. The strict candidate's residual coexists with the
rollback residual until commit. The canonical solve transfers its workspace
residual into the accepted fit; it does not leave an extra permanent N-vector.
The proposed eight-N steady vector bank was therefore rejected. The adopted
bank remains seven N-vectors, with existing strict overlap charged separately.

The scalar ten-million-row K=51 constrained fixture still selects Low and
rejects Fast at its original 36.3 GB available limit. With its historical
embedding floor and zero optional metadata dimensions, modeled Low rises by
6,520 bytes to 28,988,792,570 bytes; usable budget remains 29,040,000,000.
The 6,520 bytes are the row bank plus typed boxed parent for this Linux build,
not an empirical allocation measurement. Exact and one-byte-short boundaries
are also checked. No frozen campaign limit or historical receipt was changed.

## Repository checks and inventories

The STATUS guard now inspects tracked active documents and exempts archived
source snapshots, while continuing to reject a second active status/handover
file. It validates STATUS metadata and open beta gates without requiring stale
checkpoint headings. The public PPML wrapper check uses the exact one-call
wrapper accepted in ADR 0041; an extra command, changed forwarding or obsolete
`sortpreserve` remains rejected. No public ado wrapper changed.

OLS inventory v19 preserves all F0 and reviewed replacement-boundary pins.
Action inventory v2 binds 122 native source files and 2,493 allocation-syntax
sites, including the new metadata helper. Eleven records change from v1;
`inventory-delta.json` records each one. Counts remain structural and include
conservative test-module syntax; they are not live allocation or byte counts.
The older manifests and their failed receipts remain unchanged.
