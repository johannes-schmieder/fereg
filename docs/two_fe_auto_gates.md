## Common-origin labels and the exact loss

Let \(i\) index one of the 108 aligned cells, \(j_i\) its selected first-step-16 action, \(a\in\{N,16,32\}\) the archived arm and \(b\in\{1,2\}\) a recorded execution. Let \(E_{iabj}\) be that action's observer-excluded elapsed nanoseconds and \(P_{iab,16}\) its first-step-16 stamp.

Define

\[
Q_{iab}
=
E_{iabj_i}-P_{iab,16}
+\sum_{j>j_i}E_{iabj},
\qquad
\bar Q_{ia}=\frac{Q_{ia1}+Q_{ia2}}{2}.
\]

All these values exist for all 108 contexts and three arms. Warmups validate repeatability but do not enter the fit.

For force16 this is exactly the familiar partition:

\[
\bar Q_{iN}-\bar Q_{i16}
=
\bar I_i-\bar B_i-\bar R_i-\bar U_i-\bar C_i+\bar F_i,
\]

where \(U\) is the complete original-width startup batch and \(F\) is the signed sum of later projection-action differences.

**Force32 must use its actual common-origin \(Q\).** It includes the work from 16 through 32. Its difference from the old local-32-origin gain is the measured difference between the two arms' 16-to-32 prefix costs. That difference is small but not zero in any of the 72 retained pairs: approximately −0.884 to +0.651 ms. Identical state paths do not imply identical measured clocks.

### Pool only source-proven identical-work controls

For the 36 cells in which force32 never intervenes, pool the four recorded never/force32 **phase costs**:

\[
\tilde Q_{iN}=\tilde Q_{i32}
=
\frac{Q_{iN1}+Q_{iN2}+Q_{i321}+Q_{i322}}{4}.
\]

Set \(\tilde Q_{i16}=\bar Q_{i16}\). Elsewhere set \(\tilde Q=\bar Q\).

This rule is fixed before fitting and does not depend on which timing is favourable. Pooling requires no constructor grant/install/refusal anywhere, identical complete action schedule and non-timing trajectory, steps/live counts, scientific fingerprints, routes/hierarchies and accounted resource/work fields after only the source-proven control-token normalization. For every paired action, Force32 must use exactly two more accounted bytes than Never; bind the respective preset identities and retain both original values. No other memory/work difference is exempt. Each observed memory limit is checked against its own use; differing host census values alone are permitted. The literal resource-equality predicate in the original proposal failed: all 240 paired action records have exactly two additional Force32 transport bytes. This corrected predicate is required before pooling.

The original costs and all `no_intervention` records remain intact. This is variance reduction for two controls executing the same scientific work, **not** conversion of an absent installation label into zero elapsed time or a beneficial upgrade. A cell retains one weight, not four. Report unpooled costs for the same selected model and constant references alongside the fit. Do not select a second unpooled winner or switch models after validation.

### Joint policy loss

For fitted gates \(g_{16},g_{32}\), define

\[
a_i(\pi)=
\begin{cases}
16,&g_{16}(x_{i,16})=\mathrm{Build},\\
32,&g_{16}(x_{i,16})=\mathrm{Wait},
\ \text{the same action reaches 32},
\ g_{32}(x_{i,32})=\mathrm{Build},\\
N,&\text{otherwise}.
\end{cases}
\]

Fit exactly once:

\[
\pi^\star=
\arg\min_{\pi\in\Pi}
\frac1{192}\sum_{i\in\mathcal C}
\left[
\tilde Q_{i,a_i(\pi)}
-\min_{a\in\{N,16,32\}}\tilde Q_{ia}
\right].
\]

Here \(\mathcal C\) is the set of 108 aligned cells. All original 192 cells have equal weight. The other 84 cells have no decision episode under this class, so their scientific projection-cost contribution is policy-independent; they remain in the coverage/overhead ledger and are not negative treatment labels. Their monitoring cost can still depend on the compiled predicates and must be measured in complete-command evaluation.

The oracle term is constant across candidate policies. This objective therefore exactly minimizes selected mean projection-suffix time. It charges:

- **Missed upgrade:** choose \(N\) when an observed install programme is cheaper.
- **Harmful build:** choose an installation whose cost exceeds the cheaper available programme.
- **Mistimed build:** choose 16 when waiting to 32 is cheaper, or the converse.

Do not add step-16 and step-32 regrets for one command. The programme is selected once. The empirical minimum is noisy and optimistic; report this as empirical projection-suffix regret, not unbiased true regret.

### Available features

Use the following ordered, nonnegative integer features. Their order is part of the frozen format.

|---:|---|---|

| 1 | \(p\) | Eliminated-side level count in the actual orientation |
| 2 | \(q\) | Retained-side level count |
| 3 | \(d\) | Existing maximum raw membership count across both effects |
| 4 | \(W\) | Actual admitted host worker ceiling; one without a host team |
| 5 | \(r\) | Original current RHS width |
| 6 | \(s\) | Allocated retained-bank stride |
| 7 | \(\ell(H)\) | Integer bit length of the existing aggregate progress token |
| 8 | \(\ell(D)\) | Integer bit length of the existing aggregate token sum |
| 9 | decreasing present | `classes & 1 != 0` |
| 10 | mixed present | `classes & 2 != 0` |
| 11 | stagnant present | `classes & 4 != 0` |
| 12 | provided weights | Existing boolean |
| 13 | component scaling | Existing boolean |
| 14 | packed role | Boolean |
| 15 | outcome role | Boolean |
| 16 | final role | Boolean |
| 17 | future regressor calls | Actual full-block multiplicity plus nonempty tail |
| 18 | future regressor columns | Actual unprocessed columns; no padding |
| 19 | largest future regressor width | Largest actual remaining block/tail; zero if none |
| 20 | final call pending | Zero or one |

For positive integer \(z\), \(\ell(z)=\lfloor\log_2z\rfloor+1\), implemented by integer leading-zero count.

The existing \(H,D\) machinery is retained solely as an observable **progress token**. Its stagnant value can still equal the remaining allowance; this never becomes a literal forecast of that much paid work and is never multiplied by a time price. Class bits are separate binary features, not an ordinal class-mask number. Invalid progress is not encoded as zero.

No platform, benchmark, family, input-body hash, seed, filename, host ID, clock or requested-worker count is a runtime feature. Input hashes are used only for binding and the diversity constraint below.

No new graph census is needed. \(d\) is not unique adjacency or hierarchy complexity. Exact component count is not retained by the current feature interface, although the existing topology pass computes it; degree moments and merged-cell counts are not silently added.

### Actual future demand

Derive IDs 17–20 directly from caller-owned `Demand`, without consulting fitted prices or future realized outcomes:

| Current action | Scheduled future work |
|---|---|
| Packed with \(G\) regressors | Final residual only |
| Outcome with \(G\), block \(b\) | \(\lfloor G/b\rfloor\) full blocks, any nonempty tail, final residual |
| Regressor block ending at \(e\) | Only \(G-e\) remaining columns in actual blocks/tail, then final |
| Final | None |
| One-off | None; outside this fitted episode interface |

The regressor row is an ownership definition, not a claim of treatment-label coverage. First-install regressor episodes are unknown in this revision.

This is the same immutable retained OLS owner and weights. There is no cross-command reuse, invented packed regressor call or changing-weight PPML credit. Stride contributes to actual bank traffic; it never contributes extra future RHS columns.

### Precisely bounded fitting class

Each gate is:

- Constant Defer/Wait.
- Constant Build.
- One split \(x_f\le c\), with Build on either side and Defer/Wait on the other.

For each stage separately, freeze candidate cuts before evaluating any gate pair:

1. Use all 108 untreated first-step-16 contexts for gate16 and all 72 untreated same-action step-32 contexts for gate32.
2. For each feature, sort its distinct integer values \(v_0<\cdots<v_{m-1}\).
3. If \(m<2\), there is no cut.
4. Otherwise, for \(k=1,2,3\), set
   \[
   j_k=\min(m-2,\max(0,\lfloor km/4\rfloor-1)).
   \]
   Keep the distinct cuts \(c=v_{j_k}\).
5. Use comparison `<=` and both Build orientations. Boolean features consequently have at most the single cut zero.

There are 12 non-boolean features and nine booleans: at most 45 cuts, 92 gates per stage and **8,464 gate pairs**. No deeper tree, additional feature, extra cut grid, margin parameter or alternative learner is tried.

For each pair, compute which calibration rows reach each stage. A split requires at least two distinct input-body hashes in each reachable child. Any region that prescribes Build also requires at least two such hashes. A constant Defer is always allowed. If no training row reaches stage 32, canonicalize that gate to constant Defer.

This is a limited complexity/diversity restriction, not an independence claim or performance guarantee. Two bodies can be the two seeds of one generator. It replaces v1's full Cartesian support requirement; it does not erase missing correction/regressor treatment states.

Enumerate this fixed class once and minimize the exact rational objective. No cross-validation grid or model sequence is used. The fit is permitted to return a constant policy or zero upgrades. An unhelpful result is reported and stopped, not repaired by searching until builds appear.

### Exact ties and serialization

Break exact objective ties in this order:

1. Fewer gates requiring a progress feature, IDs 7–11.
2. Fewer nonconstant gates.
3. Lexicographic gate16 then gate32 tuple `(kind, feature_id, cut, build_if_le)`.

Kinds are `0=Defer`, `1=Build`, `2=Split`. Unused fields of constants are zero. For a split, `build_if_le=1` builds for `x<=cut`; zero builds for `x>cut`. Empty/canonicalized gate32 is Defer. This tie rule applies only to exact equal observed loss; it is not a safety margin.

Offline costs and sums use arbitrary-precision rational arithmetic on integer nanosecond labels. Runtime features/cuts use checked `u128` integer arithmetic. There are no fitted floating-point price coefficients to quantize.

Use this versioned 128-byte immutable wire format, with a 64-byte header followed by gate16 and gate32, each 32 bytes:

| Bytes | Encoding |
|---|---|
| Header 0–7 | ASCII `2FEGATE2` |
| Header 8–9 | Little-endian `u16` format version 1 |
| Header 10–11 | Little-endian `u16` feature-schema version 1 |
| Header 12–15 | Little-endian `u32` total length 128 |
| Header 16 | Gate count 2 |
| Header 17–31 | Zero reserved bytes |
| Header 32–63 | SHA256 of the concatenated 64-byte gate payload |
| Each gate 0, 1, 2 | Kind, feature ID, `build_if_le`, respectively, as single bytes |
| Each gate 3–15 | Zero reserved bytes |
| Each gate 16–31 | Little-endian `u128` cut |

Constants require feature ID, orientation and cut zero. Splits require feature ID 0–20 and orientation 0 or 1. Reject unknown kinds, versions, nonzero reserved bytes, incorrect length/hash and every noncanonical field. The separate frozen fit record binds source, evidence and all fitting rules. Parsing/round-trip checks must prove the same decisions as the rational offline evaluator.

Keep general wire parsing, payload hashing and class enumeration in maintained
offline tooling. Bind the selected wire/hash to reviewed scalar runtime
predicates and prove their equivalence to the offline evaluator. Compile only
the selected dependencies: structural gates do not ship unreachable proxy-bank
or forecast machinery for this selector. No per-estimation SHA parser is
required. Preserve the lifecycle, resource charge, checked selected inputs and
Break callbacks regardless of which features the fitted gates select.

## Remaining-work forecasts and cost interpretation

The direct decision loss replaces the role of v1's scalar remaining-work price. There is **no second fitted horizon model** feeding the gate.

For review and diagnostic interpretation, the frozen fit report must contain, for every nonempty reachable gate leaf \(L\):

\[
\widehat H_{t,L}
=
\frac{\sum_{i\in L} w_i
(\mathrm{steps}^{N}_{i,\mathrm{end}}-t)}
{\sum_{i\in L}w_i},
\]

\[
\widehat I_{t,L}
=
\frac{\sum_{i\in L}w_i
(E^N_{i,\mathrm{current}}-P^N_{i,t})}
{\sum_{i\in L}w_i}.
\]

These are conditional means of remaining shared steps and incumbent current-action cost at the observed recurrence checkpoint. Report exact rational values and sample/body counts. Do not round them into a convergence allowance.

The same report gives conditional means of construction \(B\), restart \(R\), complete startup \(U\), continuation \(C\), and signed future gain where those labels exist. At 16, report Build and the fitted continuation programme's common-origin costs; at 32, report Build and Never costs from 32. Missing components remain unavailable.

**These tables are reporting-only.** They do not affect decisions, add runtime tables, supply interpolation, or require missing packed live exposure. They are forecasts for the observed feature regions, not bounds. New dimensions or demand shapes can make them inaccurate.

This is deliberate: direct loss uses the complete observed cost partition without multiplying separately fitted errors. The implementation facts still matter:

- Construction may borrow the admitted host team and fall back to serial stages under memory admission.
- Automatic applications remain scalar/team-free; there is no automatic \(1/W\) application discount.
- Initial startup acts on the original \(r\), not just currently active lanes or stride \(s\).
- Later applications retire lanes; exact zero/component-constant images may skip a cycle.
- Current continuation includes later reconstruction, correction, MAP and certificates.
- Future costs contain each actual later action in full, including its own startup/applications.

There is one construction per observed programme, no charge for sunk pre-step-16 work and no second construction charge merely because a future call reuses the installed hierarchy.

## Deterministic state machine and feature-dependent observation

### Episode identity and eligibility

An episode is selected at the **first still-live epoch-zero local16 event** after the preserved initial certificate and direct/small-direct selection, while no hierarchy is installed and the current accuracy-key optional attempt is unconsumed.

An earlier short or zero-step action leaves the episode unselected. Selection does not depend on a favourable feature, successful observation allocation or whether the model will build.

Use a caller-owned persistent state, conceptually:

```text
Unselected
Waiting32 { selected_action_id }
Terminal { reason }
```

Do not reset this state on a new accuracy/final key. It is separate from `SetupLedger`. “Terminal economic deferral” is never written as “attempted.”

### Pseudocode

```text
on action_begin:
    keep owner-level episode
    reset only action-local sample state
    if Terminal or hierarchy already installed:
        allocate no observation bank
    else if the current route/key is optional-eligible and gate16 requires progress:
        admit bank after preserved direct selection
        remember optional refusal on this action, without selecting an episode

on recurrence checkpoint:
    run existing scientific readiness/certificate ordering first
    derive optional_eligible from the preserved route and accuracy-key ledger
    if not optional_eligible: no grant and do not select an episode

    notify episode of age/epoch/action even when no log bank exists

    if correction begins before the episode finishes:
        close economics as UnsupportedCorrection; free bank; no grant

    if Unselected and optional_eligible and epoch == 0 and local == 16 and still live:
        select this action, independently of feature availability or bank admission
        a required-bank refusal in this action closes Unknown here; an earlier
        short action with a refused bank must not consume/select the episode
        if regressor/one-off role or required feature is unknown:
            Terminal(Unknown); free bank; return no grant
        if gate16(selected feature) == Build:
            Terminal(Granted); free bank; call existing route checkpoint
        else if gate32 is constant Defer:
            Terminal(Deferred); free bank
        else:
            Waiting32(this action)
            establish only gate32's remaining observation dependencies

    if Waiting32(this action) and epoch == 0 and local == 32:
        if required feature is valid and gate32(feature) == Build:
            Terminal(Granted); free bank; call existing route checkpoint
        else:
            Terminal(Deferred or Unknown); free bank

on selected action completion or correction before 32:
    Terminal; free bank; never reopen economics in another action

on actual constructor result:
    success -> existing installation, reconstruction and restart
    memory refusal -> existing consumed key and incumbent continuation;
                      economics stays Terminal
    cancellation/fatal error -> existing failure path
```

A correction before any episode also closes economics as unsupported; it must not be skipped to substitute a later action's unobserved treatment state. Full certification, correction and MAP still run normally.

A direct attempt/refusal continues to follow the existing accuracy-key ledger.
An ineligible checkpoint in a consumed key cannot select or terminalize an
unselected economic episode; a later fresh key may supply its first eligible16.
This route/ledger guard is distinct from observation-bank refusal, which must
not suppress episode selection at an otherwise eligible checkpoint. A later direct route is not suppressed by terminal economics. An already installed hierarchy is retained and reused. Economic closure grants no new authority over the global iteration budget, tolerance or scientific acceptance.

### Unknowns and supported extrapolation

Cheap dimension/demand invariants always apply. For a selected progress predicate, missing required samples, nonfinite progress, invalid target or negative/nonfinite lane activity produce Unknown/terminal economic deferral. Structural/constant gates add no all-lane activity-validation pass; existing scientific validation remains authoritative. Checked feature overflow, unsupported first-install role/epoch or insufficient memory for a required observation bank also produce Unknown/terminal deferral. None consumes the setup attempt. Allocation failure and native errors retain their existing fatal semantics.

A cheap lifecycle callback must still see the potential first-step-16 event when no observation bank exists. Otherwise an allocation refusal could silently move the episode into a later action, invalidating the fitted stopping rule.

There is no full seed/platform/worker support table and no benchmark-specific size fence. Finite new sizes, admitted worker counts and future widths may enter a learned threshold region. **That is pooled extrapolation**, especially for multiple/wider future chunks; the retained data do not validate its speed. The real future footprint is exposed to the rule, but the rule does not claim that ten unobserved chunks yield ten times a calibrated saving.

Unknown/missing-state deferrals and deliberately excluded later opportunities must be counted in reporting. Their unobserved regret is unknown, not zero.

## Overhead, memory and cancellation

The pure inference cost is at most two selected-feature comparisons per episode plus checked scalar feature extraction. The immutable model format is 128 bytes; report actual compiled metadata size. Reporting-only forecast tables stay in the fit report.

The expensive part is observation:

\[
\text{observer entry visits}
=
\sum_{\text{actually sampled }(a,t)}
q_a\,r_{\mathrm{live}}(a,t),
\]

plus \(O(r_a)\) window/activity handling and logarithms. Every live lane uses the full readiness-proxy maximum, not an early-exit approximation.

Worst case, a selected action has five samples 0/8/16/24/32. Earlier short actions can each have 0/8 samples when gate16 uses progress, so command overhead is **not** universally “five scans.” A coarse bound is

\[
2\sum_{\text{earlier sampled actions}}q_a r_a
+5q_{\mathrm{selected}}r_{\mathrm{selected}},
\]

with actual reached samples/live widths reported. If gate16 is structural, earlier short actions need no proxy scans. If both gates are structural/constant, no proxy banks are needed at all.

For a bank:

- Nominal payload is \(16r\) bytes; charge actual vector capacity.
- Admit it against the already adjusted optional FE budget.
- Charge actual revised-sidecar shell bytes only to this selected policy.
- Free it on terminal deferral, completion/correction of the selected action or economic grant.
- Free before construction; keep the recorded peak and charge every shell still live during construction.
- Insufficient optional memory defers; an actual allocator failure remains fatal.
- No runtime fitting, growing history cache, new graph scan, constructor probe or worker pool.

Use existing polling: per RHS and at most 1,024 group entries between row polls; allocation/initialization and clearing in bounded chunks. Poll before/after the bounded scorer. Constructor work units remain cancellation cadence, never a work allowance. CMG host stages join before error propagation; cancellation cannot be converted into a memory refusal or ordinary deferral. Preserve FFI panic containment, main-thread host interaction, validation-before-publication and atomic rollback.

**Uncalibrated overhead remains a risk.** The packet does not contain an exact observer-total label, and the new compiled observer is different. No ns-per-scan value or automatic overhead saving is invented. Complete-call tests must charge these costs, including easy commands with no build.
